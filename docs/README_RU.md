# claude-recall

[English](../README.md) | [Chinese / 中文](README_ZH.md)

Сотни твоих прошлых сессий Claude Code перестают быть кладбищем: говоришь «найди
сессию, где я выгружал сделки этого клиента» — и через секунду у тебя проект, метод,
ссылка на готовый артефакт и три способа этим воспользоваться.

**Как это работает:** каждую завершённую сессию маленькая LLM (haiku) сжимает в
recap-карточку; все карточки сворачиваются в один INDEX.md — строка на сессию,
грепается мгновенно. Это единая точка касания для тебя и всех твоих агентов.
Скилл в комплекте учит любую сессию Claude Code искать по индексу и возобновлять
прошлую работу.

**Без зависимостей** — один файл Python, без API-ключей (работает через твою
существующую авторизацию `claude`).

```
СЕССИЯ ЗАВЕРШИЛАСЬ → SessionEnd-хук            → recap-карточка + handoff-карточка
РЕКАПЕР (haiku)    → сжимает сессию в карточку → ~/.claude/session-recaps/<id>.md
ИНДЕКС             → строка на сессию          → INDEX.md  ← единая точка касания
ОРКЕСТРАТОР (скилл)→ find → show → finish | handoff | spawn

АВТОКОМПАКТ?       → PreCompact-хук пишет свежий HANDOFF (задача / сделано /
                     в полёте / дальше / грабли) → SessionStart вливает его
                     обратно — сессия просыпается, зная, на чём остановилась
```

Recap-карточка — десять строк YAML:

```yaml
id: c2631a96-...
project: ~/Documents/Cursor/my-crm
task: Выгрузка сделок уволенного логиста Ивановой в Google Sheet для РОПа
status: done
method: скилл export-dismissed + Sheets API
entities: [Иванова, Bitrix]
artifacts: [https://docs.google.com/spreadsheets/d/...]
next: null
```

## Три режима

| режим | ты говоришь | что происходит |
|-------|-------------|----------------|
| **finish** | «сделай ещё раз ту выгрузку, по клиенту X» | Claude находит прошлую сессию, достаёт проект + метод, повторяет задачу прямо тут |
| **handoff** | «дай команду» | `recall cmd <id>` → `cd "<проект>" && claude --resume <id>` |
| **spawn** | «открой ту сессию» | `recall open <id>` — новое окно терминала с восстановленной сессией |

Если кандидатов несколько — оркестратор не гадает, а показывает селектор:
папка проекта + дата + контекст задачи на каждого, плюс вариант «копнуть глубже».

## Установка

Вставь в Claude Code:

> Склонируй github.com/rocketmandrey/claude-recall и запусти ./install.sh. Покажи,
> что он изменил, потом спроси меня, запускать ли `recall backfill` (LLM-вызов на
> каждую прошлую сессию, ~20–40 минут на пару сотен).

Или вручную:

```bash
git clone https://github.com/rocketmandrey/claude-recall.git && cd claude-recall
./install.sh              # CLI + скилл + SessionEnd-хук + permissions
recall backfill           # опционально: проиндексировать прошлые сессии
```

`install.sh` мержит в `~/.claude/settings.json` (никогда не перезаписывает):
SessionEnd-хук (recap + handoff), PreCompact-хук handoff'а, SessionStart-хук
восстановления и permissions `Bash(recall *)` — чтобы агенты звали recall в любой
новой сессии без промптов. Дальше каждая завершённая сессия (≥15 событий)
индексируется сама, а каждый компакт/резюм проходит через handoff-карточку.
Проверка: `recall doctor`.

## Использование

Просто скажи в Claude Code:

- «найди сессию, где я выгружал сделки»
- «мы это уже делали — сделай ещё раз по клиенту X»
- «открой сессию, где мы пилили дашборд»
- «что у меня висит недоделанного?»
- «забудь ту сессию» (удаление из индекса — с подтверждением)

### Примеры

**Повторить прошлую задачу:**
> Сделай ещё раз ту выгрузку по уволенным, но по постоянным Светланы

**Открыть прошлую сессию в новом окне:**
> Открой сессию, где мы настраивали деплой — прям окошком

**Спросить, что было решено:**
> Что мы тогда решили насчёт схемы деплоя?

## CLI

| команда | что делает |
|---------|------------|
| `recall find <запрос...>` | поиск по индексу (без регистра, OR; ищи по ОСНОВЕ слова: «Ивановой» → `иванов`) |
| `recall show <id8>` | карточка сессии |
| `recall cmd <id8>` | команда возобновления (handoff) |
| `recall open <id8>` | открыть сессию в новом окне терминала (spawn) |
| `recall remove <id8>` | забыть сессию: карточка + строка индекса + tombstone |
| `recall handoff <file.jsonl>` | записать handoff-карточку (текущее состояние) сессии |
| `recall backfill` | проиндексировать старые сессии `[--days N] [--min-events N] [--jobs N]` |
| `recall index` | статистика индекса |
| `recall doctor` | проверка установки |

Env: `RECALL_DATA` (по умолчанию `~/.claude/session-recaps`), `RECALL_MODEL`
(по умолчанию haiku), `RECALL_TERMINAL` (`Terminal`\|`iTerm`), `RECALL_MIN_EVENTS` (15),
`RECALL_HANDOFF_DAYS` (30 — срок хранения handoff'ов).

## Требования и заметки

- macOS (`recall open` через AppleScript; PR для Linux приветствуются), python3 ≥ 3.9,
  залогиненный `claude` CLI.
- **Локально**: карточки и индекс не покидают машину. Но это выжимка твоих сессий —
  не коммить и не шарь папку данных.
- Рекапы идут через `claude -p` — твоя существующая авторизация, API-ключ не нужен.
  Сессии-воркеры помечены и сами никогда не индексируются.
- `recall remove` ставит tombstone — хук/backfill сессию не воскресят
  (вернуть: `recall recap <transcript> --force`).
- Handoff-карточки весят пару КБ и автоматически чистятся через 30 дней;
  долгая память живёт в recap-карточках. Сессия, открытая через `recall open`,
  получает свой handoff автоматически — просыпается, зная следующие шаги.
- Отлично сочетается с [codbash](https://www.npmjs.com/package/codbash-app) как
  полнотекстовый fallback и веб-дашборд; не обязателен.
